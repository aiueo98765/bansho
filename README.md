# 板書 — BANSHO

友だちと**同じ板**を見ながら、数学の式も図もその場で書く。
サーバーを持たない。中身が残るのは、それぞれの端末の中だけ。

**公開中 → https://aiueo98765.github.io/bansho/**

名前を入れて「新しい板をつくる」を押すと `ABC-123` のような合図が出ます。
これを友だちに伝えるだけで、同じ板に入れます。

## 手元で動かす

```bash
python scripts/serve.py 8420
```

→ http://localhost:8420

ファイルを直接開く（`file://`）と ES モジュールが読めません。必ずサーバー越しに。

## 決めごと

**サーバーを持たない。** 相手を見つけるところだけ公開リレー（nostr / MQTT）を借りて、
見つかったあとは端末どうしの直通（WebRTC）。書いたものはリレーを通らない。
板の控えは各自の IndexedDB にだけ残る。アカウントも記録もない。

**合図は六文字。** `ABC-123`。読み上げて伝えられる長さにしてある。
紛れる字（I・O・0・1）は外した。URL の `#ABC-123` でもそのまま入れる。

**数式は画像でもフォントでもなく、その場で組む。** `js/math.js` が TeX の書き方を受けて、
箱（幅・ベースラインより上の高さ・下の深さ）を積み、canvas に直接描く。
根号・大きい括弧・矢印は字ではなくパスで引く。字に頼ると伸ばしたときに崩れるため。
**何倍に拡大しても滲まない。** 画像だけは貼ったときの解像度どおり。

**ペンは線を引くのではなく輪郭を塗る。** 速さと筆圧で幅が変わり、入りと抜きが細くなる
（`inkOutline`）。図が読みやすいかどうかは、ここで決まる。
蛍光ペンだけは幅一定の乗算合成。重ねたところが濃くなる。

**手ぶれ補正は「ペン先が指を追いかける」方式**（`PULL` と `feed`）。
指の位置をそのまま線にせず、ペン先を `tip += (指 - tip) × 強さ` で寄せていく。
強くするほど滑らかになり、そのぶん遅れて付いてくる。マウスで書く人向けなので、
**ペンタブ（pointerType が pen）では遅れを 1.7 倍ゆるめる**。
指を離したときは残りの遅れを詰めてから閉じる（`catchUp`）。これを忘れると、
速く引いた線が指の手前で止まる。段は 切・弱・中・強・極の五つ、初期値は「中」。

**ペンタブにしたスマホだけは、別の勘定で補正する**（`LAG_PAD` と `padStep`）。
段はパソコンと共通だが、強さの決め方が違う。

- **遅れを拍の数ではなく距離で決める。** 一拍に `sp` px 進む手には `sp/(sp+遅れ)` で
  寄せる。釣り合ったところで、ペン先はちょうど「遅れ」px だけ後ろを行く。
  拍で決めると、位置を知らせる速さが端末ごとに違うので効きが揃わない
  （240Hz の S ペンでは、マウス向けの段はほとんど効かない。実測で確かめた）。
- **速く引けば自分からゆるむ。** 上の式は速いほど 1 に近づく。
  震えが線に出るのはゆっくり引くときだけ、遅れが目につくのは速く引くときだけなので、
  両方を同じ強さで相手にすると、どちらかが必ず不満になる。
- **速さは「向きもこめた平均」で測る。** 行き戻りの震えは足すと打ち消えるので、
  震えているだけの手を「速い」と読み違えない。進んだ長さで測ると、
  震えが大きいほど補正がゆるむ（やりたいことの逆になる）。
- **二段がけ。** 一度なました位置をもう一度なます。一段を深くするより、
  同じ遅れで細かい震えがよく落ちる。
- 指はペンより狙いが粗いので、さらに 1.35 倍きつく締める。

**なぜスマホだけ強くするのか。** 手のひらに乗る大きさの面に、パソコンの画面まるごとが
映っている。指先の一ミリの震えが、板の上では何倍にも引き伸ばされる。
同じ段でもパソコンよりずっと強く効かせないと釣り合わない。

効きは数で見られる。

```bash
node scripts/stab-test.mjs
```

震えを乗せた手を作って、引けた線が元のまっすぐからどれだけ外れたかを測る。
式は写していない（`js/board.js` の `padStep` をそのまま呼ぶ）ので、本体を直せば数も動く。
段を触ったら、これを回してから決めること。

**指二本は必ず画面の移動と拡大。** 書きかけがあっても取り消す。
ペンが触っている間は指を無視する（手のひらで線が増えないように）。

**スマホはペンタブになる。** 同じ合図の板をスマホで開いて「ペンタブ」を押すと、
スマホの面がパソコンの画面にそのまま重なる。手元は見ずに、パソコンを見ながら書ける。
やっていることは「自分のカメラを相手の見え方に合わせ続ける」だけなので、
描画も同期も普段のまま通る（`tabletFit` / `fitTablet`）。
縦横の比が違うぶんは、比を保って真ん中に置き、外は縁として落とす。

**ペンタブのスマホには、操作するものを一切出さない。** 全画面にして、道具箱も帯も
隠す。**筆の色・太さ・手ぶれ補正はパソコンが決めて、`tv` に乗せて配る**（`toolState`
／ `applyTools`）。決めるところが二つあると、どちらが効いているのか分からなくなる。

出口は右上の小さな ✕ だけ。全画面から抜けたら（戻るしぐさ・Esc）ペンタブも畳む。
**指二本でちょんと触ると「戻す」。** ボタンを出さないので、これが唯一の取り消し。

**関数のグラフは要素のひとつ。** 置いたあとも動かせるし、二度押しで式を直せる。
漸近線をまたいだところは繋がない（繋ぐと縦の嘘の線が出る）。

## 仕組み

### 板の持ちかた

要素は「時刻つきの箱」。同じ id に後の時刻が来たら差し替え、消したものは墓標を残す
（`js/scene.js`）。同じ操作が二度届いても、順番が入れ替わって届いても、全員の板が
同じ形に落ち着く。時刻が並んだときは書いた人の id で決める（全員同じ答えになる）。

戻す・やり直すは、逆の操作を**新しい時刻で流し直す**。だから相手の板からも戻る。

**一枚目のページ id は `p1` で固定。** 別々に起動した二人が同じ部屋で出会ったとき、
ページの id が食い違うと書いたものが迷子になるため。
ページは消さずに `x:1` の印を付ける。並び順は数（`o`）で持つので、
同時に足しても喧嘩しない。

### 送るもの

| | 中身 | 落ちてもいいか |
|---|---|---|
| `op` | 板への操作 | だめ |
| `lv` | 書いている最中の線 | いい |
| `cu` | 指先の位置 | いい |
| `sn` | 入ってきた人へ渡す板まるごと | だめ |
| `vw` | 画面の位置（「画面を合わせる」） | いい |
| `lz` | 指し棒 | いい |
| `tv` | 画面側 → ペンタブ「いまここが映っている」 | いい |
| `tc` | ペンタブ → 画面側「ここを映して」 | いい |

`tv` と `tc` は互いを呼び合うので、放っておくと行ったり来たりする。
**間引くが捨てない**（最後の状態は必ず遅れて送る）、**送った直後に届いた相手の姿は
ひとつ前のものとみなして合わせない**、の二つで止めてある。どちらか片方だけだと、
拡大を続けざまに押したぶんが落ちる。

線を動かしている間は一フレームごとに操作が出る。そのまま流すと詰まるので、
同じ要素は後の形だけ残して 45ms ごとにまとめる（`main.js` の `emit`／`flushOut`）。

入ってきた人には、**先にいる人のうち一人だけ**が板を渡す。
自分の id で待ち時間をずらし、受け取った人が `gt` を投げたら他の人は送るのをやめる。

### 消しゴム

なぞっている間は軽く消し、手を離したときに**一手にまとめ直す**。
そうしないと、なぞった回数ぶん戻すボタンを押す羽目になる。
「部分」を選ぶと、線の触れたところだけ抜いて残りを別の線として置き直す（`splitPath`）。

## 置き場

```
index.html        画面の骨
css/style.css     板の「まわり」だけ。板そのものは canvas
js/main.js        全部つなぐ（入口・ページ・書き出し・鍵盤）
js/board.js       手の動き → 板の上の形（道具・カメラ・選択）
js/scene.js       板の中身（時刻つきの箱・戻す）
js/render.js      描く（ペンの輪郭・方眼・グラフ・書き出し）
js/math.js        TeX → 箱 → canvas
js/expr.js        「y=2x^2-3」→ 関数
js/geom.js        外寸と当たり判定
js/net.js         相手とつなぐ
js/store.js       手元に残す（IndexedDB）
js/ui.js          道具箱と窓
vendor/trystero.js
scripts/serve.py        手元で配る
scripts/stab-test.mjs   手ぶれ補正の効きを数で見る
```

### trystero の形

この版は `room.makeAction(name)` が **`{send, onMessage}` のオブジェクト**を返す
（配列ではない）。`send(data, {target: peerId})`、`onMessage = (data, {peerId}) => …`。
`onPeerJoin` / `onPeerLeave` は**代入**（関数呼び出しではない）。
リレーは `relayConfig: {urls: [...]}`。`relayUrls` という鍵は無い。
action の名前は 32 バイトまで。

## 罠

**裏に回ったタブでは `requestAnimationFrame` が止まる。** 窓を出すときの
「`.on` を次のフレームで付ける」が効かない。一度測って確定させてから付ける
（`void back.offsetHeight`）。

**pointerdown と同じ拍で `focus()` を当てると弾かれる。** そのあとブラウザが
focus を付け替えるため。文字入力は `setTimeout(…, 0)` で当てる。
板の上では `preventDefault()` して既定の付け替えを止める。

**`wss://relay.damus.io` はよく落ちる。** 繋がらない旨がコンソールに並ぶが、
他のリレーで見つかるので実害はない。全滅したら `js/net.js` の `RELAYS` を足す。

**シェル経由でソースを書くとバックスラッシュが落ちる。** 正規表現と TeX が壊れる。
`js/*.js` はエディタで直接書く。

### スマホをペンタブにする

1. パソコンで板を開く
2. スマホで同じ合図の板を開く（共有のリンクでも可）
3. スマホの上の帯にある**ペンタブ**のボタンを押す

スマホは全画面になって、書く面だけになる（道具も帯も出ない）。
枠の中が、そのままパソコンの画面。**横向きに持つと広く使える。**

| スマホでできること | |
|---|---|
| 書く | 枠の中をなぞる |
| 戻す | 指二本でちょんと触る |
| 画面を動かす | 指二本でつまむ・枠の外（縁）をなぞる |
| やめる | 右上の ✕、または全画面から抜ける |

**筆の色・太さ・手ぶれ補正・道具はパソコンで決める。** スマホはそれをそのまま使う。
ただし**手ぶれ補正だけは、同じ段でもスマホにずっと強く効く**（上の 決めごと）。
足りなければパソコン側で「強」か「極」に上げる。強くするほど角は丸くなる。
